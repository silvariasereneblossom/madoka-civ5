# Code review — Wish for the World v27 on Community Patch 5.4.6

Date: 2026-09-16. Scope: all of `wftw/` (30.5k lines of Lua, 12.4k of SQL,
5k of gameplay XML) plus this repo's own tooling. Method: six parallel
reviewers with a shared checklist (crash safety, multiplayer determinism, CP
5.4.6 API correctness, save/load, performance, data hygiene), every finding
verified by reading the code, and the data layer cross-checked against the
simulated database (`build/sim_cp_wftw.db`). Findings already recorded in
`port-notes.md` are not repeated here.

Every reviewer independently verified that the Lua API surface WFTW uses
exists in CP 5.4.6 with matching arities. The problems below are in the
mod's own code, not in the CP port.

## Headline

1. **The mod cannot survive a Magical Girl witching out.** `TurnIntoWitch`
   indexes a table with an undeclared `iPlayer` in the non-leader branch, so
   the first non-leader MG that hits Despair raises a Lua error inside the
   per-turn upkeep, which then skips the rest of that player's MG processing
   every turn. Together with the (already fixed) schema collision this is the
   most likely shape of the historical "crashes when a Magical Girl spawns /
   despairs" reports.
2. **Several code paths are one-line crashes on common events**: any Bubble
   Bomber near any unit, every load-screen close when Shirome is in the game
   with fewer than the maximum number of civs, any Herald of Madoka Law of
   Cycles mission, Nagisa's trait when a city has no empty plots, every war
   declaration with Sayaka's Ally of Justice decision active.
3. **Multiplayer is not currently viable.** Mood recomputation writes
   promotions and persisted state from per-client UI events; UI appearance
   edits always take the single-player branch because the `bMulti` flag is
   never set in UI contexts; witch spawn plots are chosen by iterating a
   table keyed by plot userdata; `CustomMissionCompleted` returns a value
   that depends on the local active player. Each of these alone desyncs a
   simultaneous-turn game.
4. **A long tail of silent logic bugs disables whole features**: the belief
   mood modifier never matches, the radius-2 Truth spread scans the wrong
   plot, portrait accessories never load (zero-step `for`), the vacation
   loyalty penalty *maxes* loyalty instead, all 29 hidden base-game missions
   are made legal, the Halicarnassus gold never pays, and Kyouko's MG
   exclusion never applied.
5. **The data layer is in better shape than the Lua**: no column collisions
   remain, no dangling rows in the risky join tables, load order is correct.
   The real items are a renamed CP column (`BarbCampGold`) that inverts the
   intended effect, two unregistered landmark art tags (affects every
   barbarian camp), three whole files that are commented out, eight triggers
   that rewrite other mods' data, and five typos.

## E. UI layer and the CP rebase

- **UnitPanel.lua**: WFTW = vanilla + 36 hunks; CP = vanilla + 6 hunks. Masking CP loses DLL-sourced disabled-action reasons, civilian XP display, and CP's changed `GetBuildTurnsLeft` semantics (worker progress off by one). Rebase: reapply WFTW's hunks onto CP's file, ~half a day. Also delete `UnitPanel.lua:6` `include("MagicalGirlInfoPanel.lua")` (file is `import="0"`, unresolvable, and unnecessary).
- **EnemyUnitPanel.lua**: CP's is a full rewrite that takes exact damage from the DLL (`GetMeleeCombatDamage`, `GetRangeCombatDamage`) and lists ~40 CP-only modifiers. WFTW's vanilla-based copy shows **wrong combat predictions under the CP DLL** — the largest functional regression of the port. Re-implement WFTW's seven hooks on CP's file (name, portrait stack, Soul Gem readout, incubator no-counter, no-counterattack label, SGSTATE/MGMOOD modifier lines, hover targeting): one to two days.
- `CivilopediaScreen.lua`, `SetUnitName.lua`, `BarbarianCampPopup.lua`: CP has no override; deltas are small (165/29/20 lines) and rebase mechanically. Restore the two vanilla MP-invite handlers the Civilopedia copy dropped.
- Performance: two full `GameInfo.UnitPromotions()` sweeps per combat-odds refresh (`EnemyUnitPanel.lua:1112,1611`); full Appearance-tab rebuild on every unit-dirty event (`MagicalGirlInfoPanel.lua:1078`); O(cities × buildings) entertainment recount on every city-dirty event (`CityInfoStack.lua:76`, `TopPanelEntertainmentDisplay.lua:51`); two cross-context round trips per unit-dirty (`TopPanelFreezerDisplay.lua:78`).
- `MagicalGirlInfoPanel.lua:1093` hides the whole context and never unhides it (panel dies for the session); `:25` colour table `{x,z,z,w}`.
- Dead "pending appearance change" preview path with live bugs (`UnitPanel.lua:2403`, `EnemyUnitPanel.lua:180-218`).

1. A non-leader Magical Girl reaching Despair (witching out), with other MGs
   of the same player on the map: upkeep must continue past her.
2. Bubble Bomber next to any unit; Herald of Madoka's Law of Cycles; Nagisa
   founding a city with no free tiles; Shirome present in a game below the
   civ cap (reveal now fires on her first turn, once).
3. Hidden PMMM missions: no unit action lost its "always possible" path now
   that the 29 base missions are excluded.
4. Mood tooltips (Homesick moodlet returns its tooltip differently), Dull
   Pain expiry, an AI MG taking a vacation, an MG acquiring likes/dislikes
   early game (three new early-abort paths).
5. Demon Homura: melee, ranged and attrition kills each credit exactly one
   subjugation; palace dummies follow a captured/moved capital. Mami: friend
   dummies appear for a friend, never in Mami's own capital, and vanish when
   the last Teahouse civ dies.
6. Ctrl+S and F11 saves still open the menu / quicksave and persist mod data
   (reload and check MG state).
7. UI: Mood and Appearance tabs on an MG without a table record, enemy panel
   hover on such an MG, Freezer panel as Pleiades, rename of an MG.

## Positives worth preserving

- Persistence design (single `PMMM` tree, string keys, TSL serializer) and cached DB lookups in `PMMMDataStorage.lua`.
- Synced RNG everywhere; boolean `GameEvents` handlers end with explicit returns.
- Bootstrappers only include trait/UB/UU scripts for civs actually in the game.
- Data-driven mood modifiers and like/dislike categories with an `ExternalScript` extension hook.
- The Grief Seed action shows the correct MP pattern (`SelectionListGameNetMessage` + gameplay-side `CustomMissionStart`).
- All UI controls and PMMM text keys resolve; the Civilopedia delta is small and disciplined.
